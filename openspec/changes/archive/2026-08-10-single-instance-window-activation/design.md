## Context

应用入口在 `main.go` 中调用 Wails `wails.Run`，当前没有配置单实例策略。关闭主窗口时 `App.beforeClose` 使用 `runtime.WindowHide`，因此已有实例仍在后台运行，但再次启动会创建新的 Wails 应用、输入监听和提醒循环。

Wails v2.13.0 已提供跨平台 `options.SingleInstanceLock`：Windows 使用命名互斥体，Linux 使用 D-Bus 名称，macOS 使用锁文件机制。项目已依赖该版本，不需要自行维护平台锁实现。

## Goals / Non-Goals

**Goals:**

- 同一用户会话中只允许一个正式应用实例继续运行。
- 第二次启动时让已有实例显示并恢复主窗口。
- 让已有实例继续保留监控、提醒、设置和时间线状态。
- 覆盖 Wails 支持的 Windows、Linux 和 macOS 构建。

**Non-Goals:**

- 不把第二次启动参数传递给业务层。
- 不改变关闭窗口隐藏到托盘的现有行为。
- 不增加自定义锁文件、IPC 服务或第三方依赖。
- 不处理不同应用版本之间是否共用实例的升级策略。

## Decisions

- **使用 Wails 内置单实例锁。** 在 `options.App` 配置 `SingleInstanceLock`，而不是使用 `os.OpenFile(O_EXCL)` 或自行编写平台代码。前者已有原生实现并处理进程退出后的锁释放；简单锁文件会留下陈旧文件，不能可靠区分崩溃与运行中的实例。
- **使用稳定应用 ID。** 选择固定且不随工作目录变化的唯一 ID，例如 `health-tool`，确保从不同位置启动的同一正式应用仍被视为同一实例。开发模式和正式包的隔离不在本变更范围内。
- **第二实例只唤醒已有窗口。** 在 `OnSecondInstanceLaunch` 回调中调用 `runtime.WindowUnminimise` 后调用 `runtime.WindowShow`。已有窗口被隐藏时 `WindowShow` 恢复它；被最小化时先取消最小化。回调忽略启动参数和工作目录，避免引入未定义的打开文件等行为。
- **不手动退出第二实例。** Wails 的单实例实现负责在检测到已有实例后将第二个进程退出；应用回调只负责已有实例的窗口动作。

## Risks / Trade-offs

- [Linux 无法连接 D-Bus 会话总线时，Wails 可能降级为允许启动] → 接受 Wails 的平台行为；若产品要求在该环境下也必须拒绝双开，需要另立变更定义失败启动策略。
- [第二实例启动时已有实例仍处于初始化阶段] → 回调只执行窗口操作，并对尚未准备好的上下文进行保护；Wails 的单实例通知发生在桌面前端创建后。
- [开发版与正式版共用应用 ID] → 当前默认视为同一应用；若开发体验需要并行运行，再为开发配置独立 ID。

## Migration Plan

无需数据迁移。发布后首次启动获取单实例锁；退出或崩溃后由操作系统/Wails 释放锁。回滚只需移除 Wails 单实例配置，不影响设置、时间线或其他运行数据。

## Open Questions

无。第二次启动的行为已确定为显示已有主界面并退出第二个进程。
